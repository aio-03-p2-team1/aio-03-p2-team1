# 품종 검색 규칙과 변경 영향

## 조사 시점의 규칙

- `kinds`는 공공 품종 코드를 키로 축종(dog/cat/other), 공식 이름, 공백 제거 이름, 활성 상태를 저장한다. `kind_aliases`는 큐레이션 별칭이다.
- 초기화 스크립트는 전체 축종·페이지를 조회하고 코드 기준 upsert한다. 사라진 코드는 삭제하지 않고 비활성화한다. API 실패·불완전 응답은 최대 3회 재요청한다.
- 검색 런타임에는 품종 DB 조회 경로가 없다. 품종은 선택 특징이며 후보 정렬의 가중치 3에 사용된다. 공고 조회를 품종으로 제한하지 않는다.
- 글 특징 추출 LLM은 설명에 명시된 품종만 반환하며 설명에 없는 문자열은 버린다. 사진 분석은 확신 기준 0.8을 사용하지만 공식 품종 목록을 받지 않는다.
- 프론트 검색 화면은 축종·자유 설명·사진으로 조건을 받으며 품종 선택기가 없다.

## 현재 계약 (breed-v2, 사용자 요청 반영)

- `GET /api/v1/kinds?species=dog|cat|etc&name=선택`: 활성 품종을 조회하고 Redis에 축종별 1일 캐시. 기타는 DB other와 매핑한다.
- 명시적으로 전달된 품종 이름만 규칙 우선·AI DB 조회 도구 보완으로 정규화한다. 설명에서 품종을 추출하는 기능은 제거했다. 글 AI 입력/결과에 품종 필드는 없다.
- 서버 시작 시 전 축종의 활성 품종 코드·이름만 `lru_cache(maxsize=1)`에 예열한다. 정렬된 불변 tuple이며 사진 요청 시 DB 재조회는 없다. 시작 시 DB 오류는 시작 실패로 드러낸다.
- 사진 AI는 `breed_code`와 `confidence.breed_code`를 반환한다. 백엔드가 LRU 목록에 존재하는 코드인지 검증하고, 없으면 빈 문자열로 반환한다. API의 `breed`는 코드에서 얻은 공식 표시 이름이다.
- 사진의 품종은 설명에 붙이지 않고 셀렉트에 반영한다. 수동 선택은 같은 축종에서 유지하며 축종 변경 시 초기화한다.
- cron은 마지막 성공 이후 7일 경과 시 upsert·재시도 후 Redis를 무효화한다. 프로세스의 시작 시점 LRU 스냅샷은 재시작 후 반영된다. 원격 등록·배포는 별도다.

## 검증 범위

API·Redis·LIKE 조회·cron·그래프는 모의 외부 서비스 시험으로 검증한다. 사진은 코드 존재/불일치/빈 목록, 프롬프트 코드·이름 전달과 캐시 키 HTTP 전달을 검증한다. 프론트는 목록 재사용·사진 선택 반영을 node 시험과 빌드로 검증한다. 실제 외부 API·모델 품질·캐시 적중률·브라우저 수동 조작은 미측정/미검증이다.
