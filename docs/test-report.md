## 4. 수정 이력

### toy-poodle-alias-v1 (2026-11-18)

로컬 SQLite의 활성 개 품종에는 `토이 푸들`(코드 `000107`)이 있었지만 `kind_aliases`에 `푸들` 별칭 행이 없어, 동기화 전 DB에서는 분실 신고 품종 코드를 제공하지 못했다. 별칭 큐레이션을 `backend/tools/kind_aliases.py`로 모아 동기화 스크립트와 런타임이 공유하고, DB 별칭 행이 없어도 공용 별칭 원본을 적용하도록 수정했다. 동기화 별칭 행이 없는 상태에서 `푸들` 신고를 토이 푸들 코드로 반환하는 API 회귀 사례를 추가했다.

검증: 백엔드 전체 258개 통과, 프론트 `npm test` 55개 통과, `npm run build` 성공, `uv run ruff check backend` 통과. 외부 API·운영 Supabase 연동과 브라우저 실제 요청은 미측정.

전단지 도형 추가 버튼 제거(poster-toolbar-v2): 사용자 요청으로 편집 도구에서 도형 추가 버튼과 사용되지 않는 `addShape` 함수를 제거했다. 템플릿과 기존 저장 문서에 포함된 도형의 표시·편집은 유지한다.

전단지 목록·한도 수정(poster-library-v1): 마이페이지에서 내 전단지 목록을 조회하고 편집기로 불러오기·확인 후 삭제를 지원한다. 신규 저장 시 백엔드가 로그인 사용자의 DB 전단지 목록을 조회해 5개 이상이면 `poster_limit`으로 거부하며 기존 문서 수정은 허용한다. 삭제 후 신규 저장과 타 사용자 격리를 회귀 시험에 포함한다.

로컬 검증: `uv run --no-sync pytest backend/tests/test_posters.py` 7개 통과(SQLite 테스트 DB 사용), 프론트 `npm test` 48개 통과, `npm run build` 성공. 실제 Supabase 연동 및 브라우저 확인 팝업 조작은 미검증.

원격 `feat/my-posters` 병합 후 재검증: 전단지 백엔드 8개·프론트 49개 통과, 프론트 빌드 성공. 원격의 전단지 요약·상세·수정 저장 보완을 유지하고 마이페이지 중복 목록을 제거해 직접 불러오기·삭제와 5개 제한을 통합했다.

### board-breed-v1 / feature-extract-v6 (2026-11-17)

게시판의 [이 정보로 구조 공고 찾기]가 품종을 특징란에 붙이고 품종 선택값을 비우던 오류를 수정했다. 회원 글 등록을 공식 품종 셀렉트로 바꾸고 서버에서 축종별 활성 코드를 검증해 breed_code와 공식 품종명을 저장한다. 기존 글·공공데이터 분실 신고는 조회 시 공식명·별칭의 유일한 일치로 코드를 제공한다. 모호하거나 없는 품종은 빈 코드로 두고 기준정보 조회 실패는 오류로 구분한다. 검색 화면에는 코드를 그대로 전달하며 품종을 특징 문구에 추가하지 않는다. 글 특징 추출 프롬프트에 품종명·코드를 marks에서 제외하는 지침을 추가하고 프롬프트 버전과 모델 캐시 키를 v6로 올렸다.

최종 검증: main 기준 독립 브랜치에서 백엔드 전체 229개, 프론트 테스트 파일 9개, Vite production 빌드·Ruff·공백 검사 통과. 모의 기준정보로 코드 저장·공식명 보정·다른 축종/미등록 코드 거부·기존 글·분실 신고·별칭·모호한 이름·조회 실패 및 검색 미리 채우기를 검증했다. 외부 API 실제 호출·실제 LLM 판단·브라우저 시각 검수·배포는 수행하지 않았다.
