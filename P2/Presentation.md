## 팀 소개 및 역할 분담

1. **팀 소개** — 표기 문구는 **Team 다시마**. 팀명과 세계관을 소개한다. [팀명과 파비콘의 유래](ref/worldbuilding.md)
2. **팀원 소개** — 팀원별 역할과 주요 기여를 소개한다. [역할 분담과 근거 커밋](ref/team-roles.md)

## 프로젝트 개요

1. **프로젝트 소개** — 사진과 실종 정보를 바탕으로 비슷한 구조 공고를 찾고 보호센터 위치를 확인하는 서비스를 소개한다.
2. **해결한 문제** — 보호자가 공고를 하나씩 비교해야 하는 상황과, ‘흰색’과 ‘백색’처럼 같은 특징이 다르게 기록되는 문제를 보여준다.
3. **사용자 시나리오** — 사진과 마지막 목격 장소를 입력하고, 후보 공고를 비교한 뒤 보호센터 위치를 확인하는 과정을 가상 사례로 보여준다.
4. **기술 스택** — 서비스의 주요 기술과 역할을 한 장에 정리한다. React·Vite는 사용자 화면, FastAPI는 서비스 API, LangGraph와 LangChain·OpenAI는 검색 흐름과 특징 추출, Supabase·Redis는 데이터 저장과 캐시를 맡는다. 구조동물 공공 API와 카카오 지도는 외부 연동으로 표시한다. [기술 스택과 운영 구성](../docs/development.md#기술-스택)

## 전단지 기능 및 실종 신고 게시판

직접 시연하거나 녹화 영상으로 보여준다.

1. 전단지 템플릿을 소개한다.
2. 긴급형 템플릿에 사진과 실종 정보를 입력한다.
3. 완성한 전단지를 PNG로 다운로드한다.
4. 다운로드한 PNG를 실종 신고 게시글에 첨부해 등록한다.
5. 등록한 게시글에서 **Try Search**를 실행한다.

## 동물 검색 시연

1. **기능 소개** — 스크린샷으로 사진에서 특징을 추출하고 검색에 사용하는 흐름을 설명한다.
2. **시연** — 사진에서 정보를 추출한 뒤 구조 공고를 검색한다. 정보가 부족할 때 크기를 확인하거나 검색 반경을 바꾸는 흐름도 보여준다. 털색이 ‘기타’로 표시된 앵무새 공고로 검색하면서 사진에서 추출한 색상이 표시되는 장면을 보여준다.

## 검색 및 비교

공고 후보를 조회하고 순위를 매기는 과정을 설명한다.

`API에서 공고 N건 조회 → 임베딩·캐싱 → 쿼리 → RRF로 후보 재정렬`

- [ ] 현재 코드에서 실제 조회 건수와 순위 계산에 쓰는 설정값을 확인한다.

## 컬러 토크나이징

1. 실제 추출한 공고의 털색 표기를 보여준다. [털색 데이터](../docs/data/animal-color-combinations.tsv)
2. 단어 단위 매칭이 실패하는 사례를 설명한다.
3. 컬러 토크나이징으로 그 사례를 어떻게 처리하는지 보여준다. [색상 정규화 설명](../docs/color-normalization.md)
4. 아직 처리하기 어려운 패턴과 한계를 짚는다.

## 마무리

1. **한계와 개선 방향**
   - 사진에서 개체를 구별하는 데 필요한 특징을 추출하지 못하는 경우가 있다.
   - 털색·무늬 표기에 새로운 패턴이 나타나면 사전을 점검하고 갱신해야 한다.
   - 에이전트가 현재 검색 상황에 맞지 않는 다음 검색 방법을 추천하는 경우가 있다.
2. **팀원 소감** — 가로로 배치한 카드 3장에 각 팀원의 의인화 동물 캐릭터를 위에, 한 줄 소감을 아래에 넣는다.

| 팀원 | 캐릭터 | 참고 |
| --- | --- | --- |
| 이희래 | 여우 | 《주토피아》 닉 와일드 |
| 변건형 | 악어 | |
| 이서준 | 고양이 | |

- [ ] 팀원들과 아쉬웠던 점과 추가하고 싶은 기능을 정리한다.
- [ ] 에이전트가 적절한 다음 검색 방법을 추천하지 못한 원인을 분석한다.
- [ ] 팀원별 한 줄 소감을 받고 캐릭터 이미지 3장을 준비한다.
